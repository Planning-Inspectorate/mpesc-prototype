Smart evidence marking

Features that allow a user to read or unread, flag or unflag files related to a case. These statuses update instantly without a page refresh.

When to use this feature

Use this component inside document tables where users need to process high volumes of information. It allows them to:

  • keep track of what they have already reviewed (Read/Unread)
  • highlight specific files that need further attention or discussion (Flagged)

This pattern helps improve the user experience by:

  • using JavaScript (Fetch API) to silently update the database in the background
  • preventing disruptive page reloads every time a user clicks a tag
  • retaining the user's exact scroll position in long lists of files

How to implement

  1. In your Nunjucks table, ensure every tag has a dynamic ID matching the document (e.g. id="status-tag-read-{{ doc.id }}").
  2. Add the visibility: hidden; style to the "Flagged" tag when it is not active. This ensures the column width doesn't shift around when tags are toggled.
  3. Give the Action links a specific CSS class (e.g., js-read-toggle) and embed the document ID directly into the link via a data attribute (data-doc-id="{{ doc.id }}").
  4. Use Frontend Javascript to listen for clicks on those specific classes. When clicked, visually swap the Tag styling and Link text immediately, and trigger a `fetch()` request.
  5. The `fetch()` request hits the Express backend, passing the Document ID and new status, which silently saves it to the session data without interrupting the user.
